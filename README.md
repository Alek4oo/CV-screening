AI CV Screening по EU AI Act

Инструмент за класиране на кандидати спрямо роля — обяснимо, без дискриминация и с човек в цикъла. Изграден като високорискова AI система по EU AI Act (Annex III §4), с комплайънс слой: bias-одит, human-in-the-loop, прозрачност и одитни логове.

⚠️ Всички данни са синтетични. Без реални лични данни или достъп до реални системи.

Функционалности
Парсване и класиране на CV-та спрямо изисквания на роля.
Качване на CV в PDF или TXT, с базов OCR за сканирани PDF-и.
Обяснимо класиране — кои умения/фактори тежат и защо.
Изглед за рекрутер с преглед и ръчно решение (никакво авто-отхвърляне).
Bias-одит: сравнение на класирането със и без чувствителни признаци (пол/възраст/произход).
Одитни логове на всяко решение (вход, изход, версия на правилата, кой е потвърдил).
Архитектура

Модулен монолит (modular monolith) с hexagonal подредба на модулите — едно приложение, един деплой, с ясно обособени вътрешни модули и строги граници между тях. Правилният размер за соло/двама: чистото разделяне на отговорностите от микросервисите, без мрежовата сложност на разпределена система.

Ключови решения:

Сменяеми адаптери (strategy pattern) за OCR (extract_text(file) -> str) и скоринг (score(candidate, role) -> Result) — реализацията се сменя тривиално.
Комплайънс слоят е cross-cutting — маскира защитени атрибути преди скоринга, пуска bias-одита и пише в неизменим одитен лог.
Human-in-the-loop е състояние в потока, не бутон — нищо не става „отхвърлено" автоматично.
Версионирани правила (ruleset_id) — всяко решение сочи към версията, с която е взето.

Поток на данните: качване → OCR → структуриран профил → маскиране на защитени полета → скоринг спрямо роля → обяснение → рекрутер преглежда (HITL) → потвърждава/отменя → запис в audit_log. Bias-одитът работи офлайн върху целия набор.

Защо релационна база

Данните са силно свързани (кандидати ↔ роли ↔ решения ↔ правила ↔ одит), а одитната следа иска ACID и неизменимост — силните страни на релационния модел. Гъвкавите, вариращи CV полета се пазят в JSONB колони; евентуален семантичен матчинг — през pgvector. Всичко в една база, без отделна NoSQL система.

Стартиране

Изисква Docker и docker-compose.

bash
git clone <repo-url>
cd cv-screening
cp .env.example .env
docker-compose up --build

Приложението тръгва на:

Frontend: http://localhost:3000
API + документация: http://localhost:8000/docs

Локално стартиране (без Docker)

Изисква Python 3.11 и Tesseract с езиковите пакети bul+eng. Растеризирането на сканирани PDF-и е на pypdfium2 (колело от PyPI) — системен poppler не трябва.

bash
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload

Настройките идват от backend/.env (виж .env.example). За бърз старт без Postgres:

DATABASE_URL=sqlite:///./dev.db
TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe # само ако не е на PATH

Качване на CV — приемат се PDF (с текстов слой или сканиран) и TXT:

bash
curl -F "file=@tests/data/sample_cv.pdf;type=application/pdf" http://127.0.0.1:8000/candidates/upload

Класиране за роля

POST /roles/{id}/rank класира кандидатите по активната версия правила и връща скор + принос на всеки фактор. Ролята казва какво се иска, ruleset-ът — колко тежи:

role.requirements:
{
  "required_skills": [{"name": "python", "weight": 3}, "postgresql"],
  "preferred_skills": ["docker"],
  "min_years_experience": 4,
  "min_degree": "bachelor",
  "languages": ["english"]
}

ruleset.definition:
{
  "weights": {
    "required_skills": 0.50,
    "preferred_skills": 0.15,
    "experience": 0.25,
    "education": 0.10,
    "languages": 0.00
  }
}

Скорът е 100 × Σ(тежест × изпълнение) / Σ(тежест) по факторите, за които ролята има изискване. Изричните тежести са пълни — фактор, който не е изброен, тежи нула. Класирането е в режим masked и сочи към ruleset_id; непокритият минимум вдига флаг meets_minimum=false, но не отхвърля никого.

bash
curl -X POST http://127.0.0.1:8000/roles/<role-id>/rank
curl -X POST http://127.0.0.1:8000/roles/<role-id>/rank -H "Content-Type: application/json" -d '{"ruleset_version": "2026.08.1"}'

Seed данни

Синтетичен набор за разработка и демо: една активна версия правила, две роли и шест кандидата. Пуска се ръчно и е идемпотентен — повторното изпълнение обновява, вместо да дублира (ключът е external_ref):

bash
docker-compose exec backend python -m app.seed   # в контейнер
python -m app.seed                               # локално, от backend/

Кандидатите се раждат от суров CV текст през същия парсер като продукционния път, а защитените признаци (пол, възрастова група, произход) се попълват само тук — те не идват от CV-то и служат единствено на bias-одита. Всички данни са измислени.

След seed класирането е на един curl разстояние:

bash
curl -X POST http://127.0.0.1:8000/roles/<role-id>/rank

Тестове
bash
docker-compose exec backend pytest

Покрити са ключовите елементи: логиката на скоринга, explainability изходът и bias-одитът.
